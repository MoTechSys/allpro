# 05) بروتوكول استقبال بحوث الوكلاء — خط التجميع

**الغرض:** كل تقرير يصل من وكلاء المالك (بحوث SERP، مقارنات جوجل، بيانات Google Ads، بيانات Search Console) يمر بخط ثابت:

```
inbox/ (كما وصل، بلا تعديل)  →  تحليل وتوثيق  →  analyzed/ (تحليلي + الحكم)  →  دمج في الخطة المتكاملة (reports/10)
```

## قواعد الخط

| القاعدة | التفصيل |
|---|---|
| الأصل لا يُمس | التقرير الوارد يُحفظ في `inbox/` باسم `YYYY-MM-DD-<المصدر>-<الموضوع>.md` كما هو |
| كل ادعاء يُتحقق منه | سابقة موثقة: باحث خارجي ادّعى عدم وجود GBP وكان مخطئاً (RESEARCH-INTAKE-2026-08 §0). لا نبني على ادعاء واقعي قبل التحقق |
| التحليل منفصل | لكل تقرير وارد ملف مقابل في `analyzed/` بنفس الاسم: ✅ نتبنّى / ❌ نرفض ولماذا / 🔁 مكرر مع خطتنا / ⚠️ يتعارض مع قواعد المالك |
| قواعد المالك فوق أي توصية | لا تسعير، لا أرقام غير موثقة (proof.json)، لا ترقيع، Next.js 14 SSG، لا لمس keif-v2 |
| الخلاصة تصب في الخطة | كل دفعة تحليل تحدّث `01-keif-aldiafa/reports/10-الخطة-المتكاملة-الشاملة.md` بنسخة مرقمة |

## بيانات Google Ads / Search Console الواردة
تُحفظ خام في `01-keif-aldiafa/data/gsc/` و `01-keif-aldiafa/data/ads/` (JSON/CSV كما صُدّرت) + ملخص تحليلي في `analyzed/`.
