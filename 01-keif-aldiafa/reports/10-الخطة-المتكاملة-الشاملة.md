## القسم 3: خطة الموجات الموحّدة (W1→W7 + W0)

> الترتيب من خطة v2 مع إدماج مكتسبات كل التقارير. كل موجة: هدف → مهام بدليل → معايير قبول → قياس بعدي.

### W0 — أساسات معمارية خفيفة (تمهيد إلزامي، لا ترقيع فوق هشاشة)
مأخوذة من تقرير 01 — فقط ما تعتمد عليه الموجات التالية:
- `src/lib/site-config.ts`: توحيد SITE_URL/الهواتف/البراند (بدل التكرار ×16)
- ربط locations↔serviceCity عبر `cityId` ثابت بدل مطابقة الاسم العربي النصي (`locations/[city]/page.tsx:225`)
- **قبول:** tsc + lint + build + guards نظيفة؛ صفر تغيير في HTML الناتج (diff فارغ للعناوين والمحتوى)

### W1 — العناوين والأوصاف (أسرع أثر تجاري)
- المصدر: TITLES-COPY.md **بعد تطبيق قراري C1/C2** — عناوين ≤50 حرفاً قبل البراند، خطّاف واحد قوي، وصف يبدأ بـ✓ قيمة، CTA واتساب بلا لغة تسعير وبلا أرقام غير موثقة
- الملفات: `localContent.tsx:73-84` + `locations/[city]/page.tsx` (title الـ hub بلا قهوجيين/صبابين — منع cannibalization)
- **قبول:** S1-S4 صفر أخطاء؛ كل عنوان نهائي ≤60 شامل البراند؛ صفر تكرار بين 48 صفحة
- **قياس:** GSC بعد 21 يوماً — هدف قهوجيين 0.2%→≥2%، صبابين 1.2%→≥4%

### W3 — Schema/AEO (قبل W2 لأنها أرخص وأسرع أثراً على الكيان)
- `generateProfessionalServiceSchema()` بلا address/geo + serviceArea GeoCircle + @graph موحّد بـ @id + provider مرجع @id فقط (`schema.ts:239`)
- `robots.ts`: GPTBot / Google-Extended / PerplexityBot / ClaudeBot صراحة + route llms.txt (المحتوى جاهز في تقرير 07)
- إجابات مباشرة 40-60 كلمة أعلى صفحات المال (فقرة lx-lead في LocalServicePage:238)
- ربط GBP: sameAs بالمعرّفات **المؤكدة فقط** (kgmid موثّق: /g/11vz4gzwn_) + NAP مطابق
- تحديث docs/SEO.md بالقرار الجديد (C4)
- **قبول:** Rich Results Test نظيف؛ صفر LocalBusiness/address في JSON-LD (يحرسه S-guard)؛ curl /llms.txt يعمل

### W2 — الأداء (الخانق: JS لا الشبكة — دليل: TTFB 21ms مقابل render delay 2,745ms)
- gtag 344KB: تأجيل عبر تفاعل المستخدم أو Partytown/lazyOnload مدروس (حل جذري واحد يُختار بقياس، لا خلط طرق)
- M-1: هيرو الجوال — مسار واحد فقط (إما picture/source أو priority الخاص بـ next/image، وحذف preload اليدوي المزدوج)
- M-2: تحميل أوزان 800/900 فعلياً أو التخفيض إلى 700
- M-6: حذف Particles/GoldenSparkle أو حصرها بالديسكتوب + useReducedMotion
- **قبول:** Lighthouse موبايل ≥85، LCP ≤2.5s، TBT ≤200ms (قياس قبل/بعد موثق في allpro)

### W6 — CI الحارس الآلي (قبل جراحة المدن — حتى تمر الجراحة تحت بوابة صارمة)
- `.github/workflows/ci.yml` من تقرير 08 (جاهز): build + seo-guard + similarity (SIM_MAX=0.55) + no-JS content + WCAG 2.2 + LHCI
- **قبول:** أول run أخضر على main؛ أي PR لاحق لا يُدمج إلا بعبور البوابة

### W4 — جراحة صفحات المدن (الأعمق أثراً، تحتاج غطاء W6)
تصنيف الـ32 صفحة (24+8) حسب GSC:
- **رابحة** (qahwajiin-riyadh 2,744 ظهور، jeddah…): تعميق حقيقي — content modules لكل مدينة (أحياء فعلية، حالات، أسئلة محلية، صور المدينة) حتى ينزل التشابه ≤55%
- **مريضة** (ظهور بلا نقرات): علاج نية + إجابة مباشرة + روابط داخلية
- **ضعيفة** (صفر ظهور 90 يوماً): دمج + 301 إلى hub المدينة — تقليص المصفوفة بدل تضخيمها (علاج doorway الجذري)
- **قبول:** similarity-check ≤55% لكل الأزواج؛ خريطة 301 موثقة؛ Coverage في GSC يتحرك من 9/47 صعوداً

### W5 — الرئيسية + /services
- الرئيسية: معالجة M-3/M-5/M-7/M-8 + أقسام تسويقية ناقصة (خدمات مصغرة، CTA ختامي) وفق مواصفة تقرير 05 الجاهزة
- /services (مركز 34.5): إعادة بناء كصفحة hub نية تجارية + عنوان جديد ضمن نظام W1
- **قبول:** حراس + Lighthouse لا تتراجع عن أرقام W2

### W7 — تشغيلي (مهام المالك بمساندتنا)
- GBP: منشورات دورية + ردود مراجعات + رفع 4.5→4.7 (G1/G2)
- OG مخصص: dynamic OG عبر next/og لكل serviceCity (G6 — كود لا 48 صورة يدوية)
- حماية الصور: IPTC/XMP موحد لكل المكتبة + فقرة DMCA في /legal (تقرير 06)

### النشر إلى الإنتاج (خارج الموجات — بأمر المالك فقط)
1. بعد اكتمال الموجات المعتمدة وقياساتها على العمل

3. النشر إلى keif-v2 دفعة واحدة بأمر صريح منه — ثم مراقبة GSC/Lighthouse أسبوعين
